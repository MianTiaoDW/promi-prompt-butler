# 提示词生成管家视觉优化方案

日期：2026-10-10  
实施基准：`prompt-butler/src/`，构建输出为 Chrome 当前加载的 `prompt-butler/dist/`。  
状态：已实施层级与材质优化。最新用户修订优先于本文原始蓝色方向：改为近黑背景、绿色强调和中性灰表面层级，去除大面积蓝光；保留收藏夹叠层效果。最新截图位于 `visual-review-2026-10-10/black-green/`。

## 1. 设计目标与审查边界

将插件设计成安静、清晰、有光学层次的创作工作台。采用图 4 的蓝黑环境光、图 3 的内容秩序、图 1 的局部磨砂玻璃和图 2 的主操作层级。

本方案基于四张参考图、正式项目源码与已有交接文档。尚未完成当前插件的逐屏浏览器截图审查；有关实际拥挤、遮挡和对比度的判断需在原型验收时确认。源码中已经存在创作标题、输入区、专家/技能配置、生成按钮和结果区，应优化这些现有结构，不重做业务流程。

只调整视觉、排版、布局和现有交互反馈。保留所有入口、数据、API、收藏行为、窗口拖拽与置顶能力。独立 Lab 的 Mock 和未确认图标资产不接入正式插件。此前已应用的蓝色样式作为过渡版本，不视为最终设计。

## 2. 核心诊断

| 问题或待验证风险 | 原因 | 优化方向 |
| --- | --- | --- |
| 换色无法建立主次 | 通用颜色与圆角变量不能表达组件的重要程度 | 按输入、结果、配置、导航分别定义视觉权重 |
| 全局圆角放大可能失去节奏 | 小控件、内容卡和外壳共享过少的形状规则 | 建立按用途区分的圆角体系 |
| 通用 glass-card 与专用业务面板材质不一致 | 创作和图库大量使用专用 CSS，通用类只覆盖部分界面 | 审查实际使用的选择器，逐屏映射到同一材质体系 |
| 蓝色大面积铺开容易影响内容 | 当前背景渐变与蓝灰表面会同时争夺注意 | 蓝光集中在上方，正文落在中性深色底上 |
| 文字辅助层可能显得细碎 | 描述、字数、最近使用、状态、标签同时出现 | 调整位置、字号与间距，保留必要信息 |
| 精致感缺少光线逻辑 | 圆角、边框和阴影需要共同形成厚度 | 统一左上入光、顶部内高光、下方柔阴影 |

## 3. 页面层级

每个页面按四层组织：

1. **任务层**：页面标题、当前输入或当前结果，第一眼即可识别用途。
2. **操作层**：当前主要操作，使用最高按钮对比度；同一可见任务区只出现一个主按钮。
3. **辅助层**：专家、技能、尺寸、分类、筛选，采用中性表面和较小字号。
4. **系统层**：连接状态、计数、设置、置顶等，保持可发现，降低视觉重量。

现有品牌栏与工作区导航保留。品牌栏负责身份和系统控制；工作区导航负责创作、提示词库、图像工坊切换，两者不与页面主标题争夺注意。

## 4. 配色、排版与尺寸规范

以下为建议初值，最终须在实际渲染后调整并测量对比度。统一写入语义变量，禁止散落组件硬编码。

| 用途 | 建议值 | 使用规则 |
| --- | --- | --- |
| 画布 | `#080B12` | 整体低亮度基底 |
| 阅读表面 | `#141820` | 提示词正文、设置表单 |
| 抬升表面 | `#1C2230` | 弹窗、展开配置 |
| 环境蓝 | `#245BD8` | 上方背景光，逐渐过渡到深蓝黑 |
| 主操作 | `#3D73F5` | 生成、保存配置等主要动作 |
| 蓝色文字/图标 | `#A8C5FF` | 选中、链接、焦点，不用深蓝小字 |
| 正文 | `#F2F4F8` | 正文和核心标题 |
| 辅助文字 | `#A9B1C0` | 说明、时间、元信息 |
| 普通边界 | 白色 8%–12% | 结合相邻底色测量，不单独判断 |

蓝光主要分布在页面上方约 25%–35%，使用径向光团叠加纵向衰减，避免整页均匀渐变。参考图 4 的紫色只用于主按钮极少量光泽，普通导航、卡片和标签不使用紫色。

连接成功仍采用克制的绿色，错误采用红色，警告采用琥珀色；状态同时提供文字或图标，不只靠颜色。

字体沿用系统字体栈。窄窗口页面标题 26–28px/1.2，宽窗口 30–32px/1.2，字重 500–600；模块标题 16px/1.4、600；正文和输入 14px/1.65；元信息 12–13px/1.5。中文标题避免额外宽字距，英文大标题适度收紧。JSON 使用等宽字体，保留缩进与横向滚动。

间距基于 4/8/12/16/24/32px。窄窗口内容边距 16–20px，模块间距 24px，卡片内边距 16–20px；长文本阅读宽度约 60–70 个字符。外壳圆角 28px，主要输入和模态 24px，内容卡片 18–20px，表单控件 12–14px，主按钮胶囊，图标按钮圆形。

## 5. 材质系统

### A. 环境底层

背景承担氛围，内容承担信息。上方蓝光向深黑自然衰减，图像出现后优先让图像成为色彩主角。不添加持续漂移背景、满屏颗粒或无用途网格。

### B. 内容表面

正文、生成结果、普通列表采用实底或高不透明度底色，不加 backdrop blur。用 1px 边界和极弱顶部高光分离，不给每张卡片大阴影。输入区可以比周围略亮，焦点时增加蓝色边界与弱外圈。

### C. 磨砂控制层

工作区导航、浮动操作条、短时提示采用灰蓝半透明表面，建议不透明度 78%–90%，blur 12–16px，顶部内高光白色 10%–14%，下方柔阴影。背景中需有可感知的光色变化，否则透明不会形成参考图的磨砂感。

### D. 焦点操作与模态层

主按钮使用清晰蓝色主体、顶部轻亮渐变、弱内高光和克制阴影。白色文字须实测可读性；若渐变上端过亮，应压暗按钮。模态使用更实的抬升表面与独立遮罩，避免正文透出干扰阅读。

所有材质统一左上入光。禁止所有边框发蓝、所有按钮发光、所有卡片透明，以及整窗嵌套多层模糊。低透明度偏好下改为实底。

## 6. 四个页面的具体方案

### 创作

视觉顺序：标题 → 创意输入 → 专家/技能配置 → 生成 → 结果。

- 标题左对齐，保留一句简洁说明，不加入占空间的装饰插画。
- 创意输入是首屏最大主体，初始建议高度 160–200px；窄窗口按可用高度校准，不将其固定成造成大量滚动的尺寸。
- 添加参考图、字数、清空、最近使用归入输入区下沿。上传是次要操作，清空采用低权重文字或图标样式。
- 专家与技能沿用现有展开行为，外观改成安静的配置行；当前选项清晰可读，展开控件不使用主按钮材质。
- 生成按钮紧接配置，窄窗口可采用整行胶囊，宽窗口按布局适当缩短。保持现有禁用与加载逻辑。
- 结果出现后提高结果区域视觉权重。中文正文为主要阅读面，英文和 JSON 沿用现有切换/展开方式；复制、保存、编辑按钮按功能关系分组，不全部采用亮蓝填充。
- 无结果时使用紧凑提示，避免大型空卡占据首屏。

### 提示词库

视觉顺序：搜索 → 分类与筛选 → 收藏夹 → 内容卡片。

- 搜索条保留现有行为，形状较柔和，聚焦状态比静态状态更明确。
- 工作区导航与分类控件使用不同外观：导航是磨砂分段控制，分类是轻量标签，避免两排控件看起来同级。
- 收藏夹借鉴图 4 的文件夹材质：少量后层错位、前层实底、顶部薄高光。只用于已有收藏夹，不将所有提示词都变成文件夹。
- 提示词卡片按标题、摘要、标签/时间、操作分层；标题建议最多两行，摘要约三行，详情保留全文。现有重要操作需保持键盘与触控可达，不能只在 hover 时出现。
- 有示例图的卡片可使用图 1 的图片主导方式；无图卡片使用文本结构，不添加随机装饰图片。
- 删除与编辑在动作区域区分，危险操作的红色局部使用，不污染整张卡片。
- 详情弹窗正文实底、宽松行距，底部操作区清晰；长文本滚动时关闭和必要操作可达。

### 图像工坊

视觉顺序：输入与参数 → 生成 → 本次结果。

- 输入区沿用创作页的材质语言；尺寸、数量等参数采用紧凑中性控件。
- 图片结果成为页面主角，借鉴图 2 的大封面关系；周围按钮退居辅助。
- 图片圆角 18–20px，不裁掉生成内容；完整预览保持原图比例。若网格采用裁切缩略图，应在打开预览后显示完整图。
- 图片上操作使用局部深色透明底保证对比，避免铺满整张图片的玻璃层。
- “临时结果”说明保持可见，将其与保存入口联系起来，不表现成已经永久保存的资产。
- 加载占位与结果尺寸一致，减少完成后的跳动；保留取消操作。

### 设置

- 使用比创作页更克制的环境蓝，表单采用稳定实底。
- 服务连接、模型用途、图像输出、示例图存储分别成组。组标题与字段标签建立字号差，不用层层卡片套卡片。
- 主区域突出配置表单；宽窗口状态快照放到次栏，窄窗口按顺序堆叠。
- 同一操作区以保存为主要动作，测试连接和模型发现保留各自入口，采用次要样式。
- 密钥显示、清空、备份等入口保持原行为；失败信息位于相关字段或操作附近。

## 7. 响应式、状态与动效

以实际内容宽度校准，先验收 420、680、980px，再检查 360px 最窄范围和原有最小窗口限制。420px 使用单列；680px 允许配置分组和图库双列；980px 可将创作输入与结果分栏，但结果不足时避免空白栏压缩主任务。此分栏属于布局调整，所有原入口都需保留。

图标按钮通常 40–44px，触控目标至少 44px。小窗口优先保证搜索、主操作与关闭入口完整，顶部品牌文字允许缩短显示而不删功能。

Hover：亮度、边界轻微变化；Pressed：按钮轻缩至 0.98；导航切换约 160–220ms；展开约 180–240ms，沿用现有 Framer Motion 能力。动态装饰不进入长文本区域。减少动效偏好下取消位移与缩放。

空状态提供与现有操作对应的说明；加载显示真实状态，不伪造进度百分比；错误局部呈现并保留输入；成功反馈短暂出现且不遮挡正文。键盘焦点采用可见外圈，不能依赖透明蓝边界。

## 8. 分阶段落地与验证

### 第一阶段：层级与布局

调整品牌栏、导航、四页标题、输入/结果关系、辅助信息分组和窄窗口间距。先使用基础实底验证主次，避免材质掩盖结构问题。

交付：创作空状态、创作结果、提示词库、图像工坊、设置页在 420/680/980px 的截图；各页主任务及主要按钮在 2 秒内可识别。

### 第二阶段：材质与组件一致性

完善语义颜色、按用途的圆角、输入焦点、按钮层级、磨砂导航、收藏夹叠层和结果阅读表面。逐一检查通用类与业务专用样式，避免只有部分卡片更新。

交付：组件状态对照与同屏前后比较；蓝色集中、入光一致、正文清楚；不透明阅读面和玻璃控制面可以明确分辨。

### 第三阶段：状态、动效与验收

检查长标题、长提示词、JSON、无收藏、大量分类、无示例图、图片结果、加载、连接失败、模态与滚动。验证拖拽、缩放、置顶及键盘操作。

构建要求：在 `prompt-butler` 执行 `npm run typecheck`、`npm run build`、`git diff --check`。浏览器要求：重新加载当前扩展、关闭旧窗口再打开，确认当前加载路径；真实 API 验证只使用已配置服务与既有授权范围。

验收门槛：普通文本对比度至少 4.5:1，大字号文本与必要非文本控件边界至少 3:1；透明表面按最亮/最暗背景分别测量。200% 缩放无内容或主要操作丢失。无需 horizontal 页面滚动（JSON/分类内部滚动除外）。减少透明和减少动效模式可用。

## 9. 实施文件与交付标准

- `src/styles/tailwind.css`：语义材质变量、组件和业务样式。
- `tailwind.config.ts`：按需补充语义映射，不全局盲目放大圆角。
- `src/content/OverlayApp.tsx`：顶部控制和导航视觉。
- `RolePromptStudio.tsx`、`FavoritesStudio.tsx`、`ImageStudio.tsx`：仅必要布局与样式调整。
- `src/options/OptionsApp.tsx`：设置页布局与层级。

每阶段保留必要前后截图与检查结果。最终交付必须同时满足参考风格、长文本可读性、入口完整、功能稳定四项；构建成功只能证明代码可编译，不能代替视觉验收。
